<div className={'shadow-md -ml-2 mt-[30px] mb-[5px] border p-5 rounded '}>
    [Fast](#benchmarks) and lightweight ([~80B](#bundle-size)) functions to check or assert
    that a value is a plain object.

    A plain object is a basic JavaScript object, such as `{}`, `{ data: [] }`, `new Object()` or `Object.create(null)`.

    See how it [compares to other libraries](#comparison-with-other-libraries).

</div>

## Features

- 👉&nbsp; Provide [isPlainObject](#isplainobject) and [assertPlainObject](#assertplainobject) functions.
- 🦄&nbsp; Convenience [PlainObject](#plainobject-type) typescript typings.
- 🚀&nbsp; Faster than most alternatives, see [benchmarks](#benchmarks).
- 📐&nbsp; Lightweight (starts at [~80B](#bundle-size))
- 🛡️&nbsp; Tested on [node 20-26, bun, browser, cloudflare workers and runtime/edge](#compatibility).
- 🙏&nbsp; Works cross-realms (node:vm runInNewContext,...)
- 🗝️&nbsp; Available in ESM and CJS formats.

## Usage

### isPlainObject

```typescript
import { isPlainObject } from "@httpx/plain-object";

// ✅👇 True
isPlainObject({}); // ✅
isPlainObject({ key: "value" }); // ✅
isPlainObject({ key: new Date() }); // ✅
isPlainObject(new Object()); // ✅
isPlainObject(Object.create(null)); // ✅
isPlainObject({ nested: { key: true } }); // ✅
isPlainObject(new Proxy({}, {})); // ✅
isPlainObject({ [Symbol("tag")]: "A" }); // ✅

// ✅👇 (node context, workers, ...)
const runInNewContext = await import("node:vm").then(
  (mod) => mod.runInNewContext
);
isPlainObject(runInNewContext("({})")); // ✅

// ❌👇 False

class Test {}
isPlainObject(new Test()); // ❌
isPlainObject(10); // ❌
isPlainObject(null); // ❌
isPlainObject("hello"); // ❌
isPlainObject([]); // ❌
isPlainObject(new Date()); // ❌
isPlainObject(new Uint8Array([1])); // ❌
isPlainObject(Buffer.from("ABC")); // ❌
isPlainObject(Promise.resolve({})); // ❌
isPlainObject(Object.create({})); // ❌
isPlainObject(new (class Cls {})()); // ❌

// ⚠️ Edge cases
//
// 👇 globalThis isn't properly portable across all JS environments
//    In Bun, globalThis is a plain object, but in other environments
//    (browser, Nodejs, edge, cloudflare, deno), it's not.
//
// 👇 process.env isn't properly portable across all JS environments
//    In Bun && cloudflare, process.env is a plain object, but in other environments
//    (browser, Nodejs, edge, cloudflare, deno), it's not.

isPlainObject(globalThis); // ✅ with Bun ❌ otherwise (browser, Nodejs, edge, cloudflare, deno)
isPlainObject(process.env); // ✅ with Bun and cloudflare ❌ otherwise (Nodejs, edge, deno)

// 👇 Static built-in namespaces aren't checked at runtime. This is a trade-off
//    to maintain the best performance and size. When statically known, they
//    are rejected at typecheck. If you need a runtime check, use a custom type
//    guard. But in most cases, you won't need to check for these as the
//    probability of writing a code that receives these as plain objects is low.
//    and probably indicates an issue in your code.

isPlainObject(Math); // ⚠️✅ return true, typecheck error
isPlainObject(JSON); // ⚠️✅ return true, typecheck error
isPlainObject(Atomics); // ⚠️✅ return true, typecheck error
isPlainObject(Reflect); // ⚠️✅ return true, typecheck error
isPlainObject(Intl); // ⚠️✅ return true, typecheck error
isPlainObject(WebAssembly); // ⚠️✅ return true, typecheck error
isPlainObject(Temporal); // ⚠️✅ return true, typecheck error
isPlainObject(Temporal.Now); // ⚠️✅ return true, typecheck error
```

### assertPlainObject

```typescript
import { assertPlainObject } from "@httpx/plain-object";
import type { PlainObject } from "@httpx/plain-object";

function fn(value: unknown) {
  // 👇 Throws `new TypeError('Not a PlainObject')` if not a plain object
  assertPlainObject(value);

  // 👇 Throws `new TypeError('Custom message')` if not a plain object
  assertPlainObject(value, "Custom message");

  // 👇 Throws custom error if not a plain object
  assertPlainObject(value, () => {
    throw new HttpBadRequest("Custom message");
  });

  return value;
}

try {
  const value = fn({ key: "value" });
  // ✅ Value is known to be PlainObject<unknown>
  assertType<PlainObject>(value);
} catch (error) {
  console.error(error);
}
```

### isStaticBuiltInClass

<Callout type="warn">

Deprecated since v2.3.0: static built-in namespaces (`Math`, `JSON`, `Intl`, `Temporal`...) are rejected at typecheck by `isPlainObject` and `assertPlainObject` when statically known. If you need a runtime check, create a custom typeguard.

</Callout>

```typescript
import { isPlainObject } from "@httpx/plain-object";

const isStaticBuiltIn = (v: unknown) =>
  v === Math || v === JSON || v === Atomics || v === Reflect || v === Intl;

if (isPlainObject(value) && !isStaticBuiltIn(value)) {
  // value is a plain object, but not a static built-in namespace
}
```

### PlainObject type

#### Generic

`isPlainObject` and `assertPlainObject` accepts a generic to provide type autocompletion. Be aware that no runtime check are done. If you're looking for runtime validation, check zod, valibot or other alternatives.

```typescript
import { isPlainObject } from "@httpx/plain-object";
import type { PlainObject } from "@httpx/plain-object";

type CustomType = {
  id: number;
  data?: {
    test: string[];
    attributes?: {
      url?: string | null;
      caption?: string | null;
      alternativeText?: string | null;
    } | null;
  } | null;
};

const value = { id: 1 } as unknown;

if (isPlainObject<CustomType>(value)) {
  // ✅ Value is a PlainObject with typescript autocompletion
  // Note that there's no runtime checking of keys, so they are
  // `unknown | undefined`. They will require unsing `?.` to access.

  const url = value?.data?.attributes?.url; // autocompletion works
  // ✅ url is `unknown | undefined`, so in order to use it, you'll need to
  //    manually check for the type.
  if (typeof url === "string") {
    console.log(url.toUpperCase());
  }
}
```

#### PlainObject

```typescript
import { assertPlainObject } from "@httpx/plain-object";
import type { PlainObject } from "@httpx/plain-object";

function someFn(value: PlainObject) {
  //
}

const value = { key: "value" } as unknown;
assertPlainObject(value);
someFn(value);
```

### redux/isPlainObject

100% compatible see tests.

### zod/util.isPlainObject

Zod is faster on node because it relies on the `constructor` property (cheap inline-cached property reads) rather than walking the prototype chain with `Object.getPrototypeOf`. The trade-off is that it can be fooled by inherited or user-defined `constructor` keys:

```typescript
isPlainObject(Object.create({})); // ❌ false, zod ✅ true (prototype isn't Object.prototype)
isPlainObject({ constructor: class Cls {} }); // ✅ true, zod ❌ false (a regular data key)
```

> See [zod proposal](https://github.com/colinhacks/zod/pull/5972)

### @sindresorhus/is-plain-obj

This library wouldn't be possible without [@sindresorhus](https://github.com/sindresorhus) [is-plain-obj](https://github.com/sindresorhus/is-plain-obj). Notable differences:

- [x] Faster on bun (1.77x), on par on node, and lighter
- [x] ESM and CJS formats.
- [x] Named export.
- [x] Smaller bundle size.
- [x] Provide a `PlainObject` type and `assertPlainObject` function.
- [x] Typescript convenience `PlainObject` type.

Since v2, it diverges from `is-plain-obj` by

- [x] Static built-in namespaces (Math, JSON, Intl, Temporal...) are considered as plain objects at runtime, but rejected at typecheck when statically known.
- [x] `[Symbol.iterator]` is considered as a valid property for plain objects.
- [x] `[Symbol.toStringTag]` is considered as a valid property for plain objects.`
